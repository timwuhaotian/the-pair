Dashboard + Onboarding 设计决策

空状态处理方案对比

A

方案 A: 保留 Onboarding 独立页面

首次启动 → 引导式向导 → 完成后进入 Dashboard
适合：复杂配置流程，需要详细讲解的产品

B

方案 B: Dashboard 空状态内嵌引导

始终显示 Dashboard → 无 Pair 时展示精美空状态 + 快捷创建
适合：轻量产品，用户可以"边用边学"

C

方案 C: 混合方案（推荐）

首次启动 → 3 步轻量引导（1 分钟）→ 进入 Dashboard
空状态保留"创建第一个 Pair"按钮和简短说明
平衡：有引导但不阻塞，空状态不空洞

💡 关于 Onboarding 的思考

The Pair 的核心复杂度在哪里？

复杂度分析
配置项 必须首次配置？ 可否边用边配？
工作目录 ✅ 必须 —
Mentor 模型 ⚠️ 建议 可用默认值
Executor 模型 ⚠️ 建议 可用默认值
最大迭代次数 ❌ 否 有默认值 10
技能文件 ❌ 否 按需附加

结论： 真正必须在首次配置的只有"工作目录"。模型选择有推荐默认值，其他配置都可以后续调整。
