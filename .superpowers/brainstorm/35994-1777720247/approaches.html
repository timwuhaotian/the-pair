v1.5.0 Dashboard 重构 - 三种方案

聚焦：Dashboard 信息架构 + 操作入口 + 空状态处理

A

方案 A: 仪表盘模式（推荐）

核心理念： 主页即指挥中心，一屏掌控全局

Pros

  • 顶部统计卡片（运行中/已完成/错误数）
  • Pairs 列表按状态分组，一目了然
  • 最近活动时间线在侧边/底部
  • 快捷操作浮在右下角，全局可达
  • 空状态 = 精美引导 + 一键创建

Cons

  • 信息密度较高，需要良好的折叠策略
  • 需要平衡"概览"和"详情"的边界
B

方案 B: 极简列表模式

核心理念： 少即是多，点击再展开

Pros

  • 干净的列表，每行一个 Pair
  • 悬停展开快捷操作
  • 视觉噪音极低

Cons

  • 缺少全局概览感
  • 操作入口藏得深（需要 hover）
  • 不符合你想要"一屏掌握"的目标
C

方案 C: 卡片网格模式

核心理念： 每个 Pair 一张卡片，信息丰富

Pros

  • 每张卡片展示完整状态 + 进度
  • 视觉冲击力强
  • 适合 Pair 数量较少（< 6）的场景

Cons

  • Pair 多时卡片太多，滚动体验差
  • 卡片信息密度过高会显得杂乱
  • 操作入口分散在各卡片上
