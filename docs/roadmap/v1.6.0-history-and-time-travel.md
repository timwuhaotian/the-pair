# v1.6.0 - 历史与回溯 (History & Time-Travel)

> 版本号: 1.6.0
> 主题: 历史与回溯
> 目标: 让过去的工作产生复利价值
> 预估开发周期: 2-3 周
> 依赖版本: v1.5.0（依赖其用户干预事件记录）

## 核心问题

当前的 `TaskHistoryPanel` 只是一个简单的任务列表，存在以下痛点：

- 历史任务的价值没有被充分利用
- 用户无法回到过去的某个状态重新尝试
- 无法从历史中总结"成功模式"
- 相似任务需要从零开始配置

## 功能清单

### 1. 任务 DNA 分析 (Task DNA) - P0

每个完成的任务自动生成详细的"任务画像"。

**任务画像包含:**

**概览卡片:**

- 任务名称、完成时间、总耗时
- 使用的模型组合（Mentor + Executor）
- 成功/失败状态

**效率分析:**

- 迭代次数 vs 预估迭代次数（来自 v1.4.0 的自适应预算）
- 每轮平均耗时
- 人类干预次数和类型分布
- 暂停/恢复次数

**文件改动热力图:**

- 类似 GitHub Contribution Graph 的网格
- 每个格子代表一个文件
- 颜色深浅表示修改次数
- 悬停显示文件名和改动统计

**模型表现评分:**

- Mentor 评分: 审查质量、建议有效性
- Executor 评分: 代码质量、测试通过率
- 综合评分: 1-10 分

**技术实现:**

- 新增 `task_analytics.rs` 模块
- 在任务完成时自动计算各项指标
- 存储在独立 analytics 数据库（SQLite）
- 前端组件 `TaskDNAReport.tsx`

**用户体验:**

- 打开 `TaskHistoryPanel` 不再是枯燥的列表，而是丰富的数据可视化
- 用户可以看到"上次类似任务用了 12 轮，这次用了 8 轮，进步了"

### 2. 可复用工作流片段 (Workflow Snippets) - P0

从历史任务中提取"成功模式"，供后续任务复用。

**设计细节:**

- 在 `TaskDNAReport` 中显示"成功模式"区块
- 模式识别基于：
  - Agent 的行为序列（分析→编写→测试→重构）
  - 使用的技能文件组合
  - 有效的模型配置

**模式示例:**

```
📋 检测到的成功模式:

模式 A: "测试驱动开发" (置信度 92%)
- 触发条件: 任务描述包含"测试"、"TDD"
- 行为序列: 分析 → 编写测试 → 实现 → 运行测试 → 重构
- 平均迭代: 8 轮
- 成功率: 95%

模式 B: "快速修复" (置信度 78%)
- 触发条件: 任务描述较短，聚焦单个文件
- 行为序列: 读取 → 修改 → 验证
- 平均迭代: 3 轮
- 成功率: 88%
```

**应用场景:**

- 创建新任务时，`AssignTaskModal` 显示："检测到类似历史任务，要应用其配置吗？"
- 一键应用：模型组合、技能文件、迭代上限

**技术实现:**

- 使用简单的序列匹配算法（无需 ML）
- 在 `task_analytics.rs` 中实现模式提取
- 前端组件 `WorkflowSnippetCard.tsx`

### 3. 时间旅行调试 (Time-Travel Debugging) - P1

在 `TimelinePanel` 中任意点击一个历史节点，可以回到那个状态并分叉出新的尝试。

**设计细节:**

- `TimelinePanel` 的每个节点变为可点击
- 点击后弹出选项:
  - [查看状态] - 只读查看当时的文件和消息
  - [从这里继续] - 恢复到该状态，开始新的分支
  - [对比变化] - 显示从该节点到最终的变化

**分叉机制:**

- 创建一个新的"分支会话"，继承该节点的完整状态
- 原始会话保持不变
- 分支会话在 `Dashboard` 中显示为原任务的"子任务"

**技术实现:**

- 扩展 `session_snapshot.rs`，支持"从快照恢复并创建分支"
- 新增 `branch_session()` 命令
- 快照数据结构增加 `parentSessionId` 和 `branchPoint`

**用户体验:**

- "如果当时 Mentor 让 Executor 用另一种方案会怎样？"
- 类似 Git 的 cherry-pick，但是针对 Agent 的完整上下文状态
- 降低"试错"成本

### 4. 任务对比视图 (Task Comparison View) - P2

选择两个历史任务，并排对比它们的差异。

**对比维度:**

- 配置对比（模型、技能、参数）
- 迭代过程对比（时间轴并排）
- 结果对比（文件改动 diff）
- 效率对比（耗时、迭代数、人工干预）

**应用场景:**

- "用 Claude 3.7 做 Mentor 和用 GPT-4o 做 Mentor，哪个更好？"
- "加了 `testing.md` 技能后，测试覆盖率有提升吗？"

**技术实现:**

- 新增 `TaskComparisonView.tsx` 页面
- 在 `TaskHistoryPanel` 中增加"选择对比"模式
- 使用现有的 diff 组件展示文件差异

## 数据模型扩展

```typescript
// 新增/扩展的类型
interface TaskDNA {
  taskId: string
  pairId: string
  summary: {
    name: string
    completedAt: number
    totalDuration: number
    status: 'success' | 'failure' | 'aborted'

  }

    iterations: number
    estimatedIterations: number

  modelScores: {
    mentor: number
    executor: number
    overall: number
  }
  workflowPattern?: WorkflowPattern
}

interface FileHeatmapEntry {
  path: string
  changeCount: number
  linesAdded: number
  linesRemoved: number
}

interface WorkflowPattern {
  id: string
  name: string
  confidence: number
  triggerConditions: string[]
  behaviorSequence: string[]
  avgIterations: number
  successRate: number
}

interface SessionBranch {
  branchId: string
  parentSessionId: string
  branchPoint: number // timestamp
  branchPointIteration: number
  status: 'active' | 'completed' | 'abandoned'
}
```

## 成功指标

1. **历史利用率**: 用户查看历史任务 DNA 的比例达到 60%
2. **复用率**: 通过工作流片段创建的新任务占比达到 30%
3. **分叉使用率**: 使用时间旅行功能的比例达到 20%
4. **学习效率**: 用户报告"从过去任务中学到东西"的比例（调研）

## 技术风险与缓解

| 风险                     | 缓解措施                                       |
| ------------------------ | ---------------------------------------------- |
| 分析计算影响任务完成速度 | 分析在任务完成后异步进行，不阻塞               |
| 分支会话过多导致存储膨胀 | 自动清理 30 天未访问的分支；提供"清理分支"按钮 |
| 模式识别准确率不高       | 明确标注置信度；低置信度模式不主动推荐         |
| 对比数据量大导致 UI 卡顿 | 对比视图分页加载；大数据量使用虚拟滚动         |
