# v1.8.0 - 智能辅助 (Intelligent Assistance)

> 版本号: 1.8.0
> 主题: 智能辅助
> 目标: AI 帮用户管理 AI——降低配置门槛，提升任务成功率
> 预估开发周期: 3-4 周
> 依赖版本: v1.6.0（依赖其历史数据基础）

## 核心问题

当前用户需要手动决定很多配置：

- 不知道选什么模型组合效果最好
- 不知道需要哪些技能文件
- 不知道设置多少迭代上限合适
- 配置错误导致任务失败

## 功能清单

### 1. 一键优化建议 (One-Click Optimization) - P0

基于历史数据，在 `PairSettingsModal` 和 `AssignTaskModal` 中给出配置建议。

**建议类型:**

**模型组合建议:**

```
💡 基于你的历史数据:

Claude 3.7 (Mentor) + Codex (Executor)
- 成功率: 87%
- 平均迭代: 8 轮
- 适用: 代码生成、重构

Gemini 2.5 (Mentor) + Claude Code (Executor)
- 成功率: 82%
- 平均迭代: 12 轮
- 适用: 复杂架构设计

[应用此配置]
```

**迭代上限建议:**

```
当前任务描述较长（约 500 字），建议迭代上限:
- 保守: 30 轮
- 推荐: 50 轮
- 激进: 80 轮

基于: 类似复杂度的历史任务平均需要 45 轮
```

**配置评分:**

- 对当前配置打 1-10 分
- 指出潜在问题："迭代上限可能过低"、"缺少测试相关技能"
- 提供"一键优化"按钮，自动调整到推荐配置

**技术实现:**

- 使用 v1.6.0 的 `TaskDNA` 数据
- 简单的统计规则引擎（无需 ML）
- 在 `PairSettingsModal.tsx` 和 `AssignTaskModal.tsx` 中新增建议区块
- 新增 `OptimizationEngine.ts` 模块

### 2. 技能自动推荐 (Auto-Skill) - P0

分析任务描述，自动推荐相关技能文件。

**推荐逻辑:**

| 任务关键词                | 推荐技能          |
| ------------------------- | ----------------- |
| "测试"、"TDD"、"assert"   | `testing.md`      |
| "性能"、"优化"、"慢"      | `optimization.md` |
| "安全"、"注入"、"XSS"     | `security.md`     |
| "API"、"接口"、"endpoint" | `api-design.md`   |
| "UI"、"样式"、"组件"      | `frontend.md`     |
| "数据库"、"SQL"、"schema" | `database.md`     |

**设计细节:**

- 在 `AssignTaskModal` 的 SkillPicker 上方显示"🤖 智能推荐"
- 推荐 skills 显示为可一键添加的 chips
- 每个推荐附带"为什么推荐"的简短说明
- 支持"忽略此推荐"

**技术实现:**

- 关键词匹配 + 历史成功率加权
- 技能文件元数据（在 YAML frontmatter 中定义关键词）
- 新增 `skill_recommender.rs` 模块

### 3. 异常自动诊断 (Auto-Diagnosis) - P1

当 Agent 反复报错时，自动分析错误模式并给出建议。

**诊断场景:**

**场景 A: 权限问题**

```
⚠️ 检测到问题:
Agent 连续 2 次遇到 "Permission denied" 错误

建议:
- 尝试以管理员模式运行 The Pair
- 或者修改目标目录权限: chmod 755 src/

[尝试修复] [忽略]
```

**场景 B: 模型理解偏差**

```
⚠️ 检测到问题:
Agent 似乎对项目结构感到困惑（多次读取不存在的文件）

建议:
- 加载 `project-guide.md` 技能文件
- 或者在任务描述中补充项目结构说明

[加载技能] [补充说明]
```

**场景 C: 无限循环**

```
⚠️ 检测到问题:
Agent 在文件 A 和文件 B 之间反复修改，可能陷入循环

建议:
- 暂停任务并查看当前修改
- 或者给 Agent 更明确的修改范围

[暂停查看] [添加约束]
```

**技术实现:**

- 在 Rust 后端 `message_broker.rs` 中集成诊断规则
- 错误模式使用正则表达式匹配
- 诊断结果通过 Tauri 事件推送到前端
- 前端组件 `AutoDiagnosisToast.tsx`

### 4. 智能任务模板 (Smart Task Templates) - P2

基于历史成功任务，自动生成任务描述模板。

**模板示例:**

**代码生成模板:**

```markdown
## 任务

[描述需要实现的功能]

## 要求

- [ ] 编写单元测试
- [ ] 遵循现有代码风格
- [ ] 更新相关文档

## 参考

[相关文件或链接]
```

**Bug 修复模板:**

```markdown
## 问题

[描述 Bug 现象]

## 复现步骤

1. [步骤 1]
2. [步骤 2]

## 预期行为

[描述应该发生什么]

## 实际行为

[描述实际发生什么]
```

**设计细节:**

- 在 `AssignTaskModal` 中增加"从模板开始"选项
- 模板根据历史任务自动提取
- 用户可编辑和保存自己的模板

**技术实现:**

- 从历史任务的描述中提取结构
- 使用简单的文本聚类（无需 ML）
- 模板存储在用户本地配置中

### 5. 迭代预算智能调整 (Smart Budget Adjustment) - P2

在任务运行过程中，动态建议调整迭代上限。

**触发条件:**

- 进度良好（已解决主要问题）→ 建议降低上限，避免过度优化
- 进度缓慢（核心问题未解决）→ 建议提高上限
- 已接近上限但接近完成 → 建议追加 10 轮

**设计细节:**

- 在 `IterationProgress` 组件中显示调整建议
- 用户一键接受或忽略
- 调整后立即生效

## 技术风险与缓解

| 风险                         | 缓解措施                                        |
| ---------------------------- | ----------------------------------------------- |
| 建议准确率不高导致用户不信任 | 显示置信度和历史依据；低置信度建议不主动展示    |
| 自动诊断误报                 | 保守策略，多次确认后才提示；提供"忽略此类诊断"  |
| 规则引擎难以扩展             | 规则使用声明式配置（JSON/YAML），方便添加新规则 |
| 历史数据不足导致建议无效     | 新用户显示通用建议；积累 5 次任务后启用个性化   |
