# v1.4.0 - 认知透明化 (Cognitive Transparency)

> 版本号: 1.4.0
> 主题: 认知透明化
> 目标: 让用户真正"看懂"AI在做什么
> 预估开发周期: 2-3 周

## 核心问题

当前用户看到 Mentor/Executor 在运行，但存在以下痛点：

- 不知道 Agent 具体在思考什么
- 不知道 Agent 卡在哪里、为什么做出某个决定
- 迭代进度条只是数字，缺乏语义信息
- 长时间运行时代理状态不透明，用户焦虑感强

## 功能清单

### 1. 实时意图标签 (Live Intent Chips) - P0

在 `TurnCardView` 上方浮动显示当前 Agent 的"意图"。

**状态映射表:**

| Agent 行为    | 意图标签 | 图标 | 颜色   |
| ------------- | -------- | ---- | ------ |
| 分析代码结构  | 分析中   | 🔍   | blue   |
| 编写/修改代码 | 编写中   | 📝   | green  |
| 运行测试/命令 | 验证中   | 🧪   | amber  |
| 审查/评估     | 审查中   | 👁️   | purple |
| 等待响应      | 等待中   | ⏳   | slate  |
| 处理错误      | 处理错误 | ⚠️   | red    |

**技术实现:**

- 扩展 `TurnCard` 数据结构，增加 `intent: AgentIntent` 字段
- 在 `process_spawner.rs` 中解析 JSON 事件流，提取 `tool_call` 类型
- 在 `TurnCardView.tsx` 中添加浮动意图标签组件
- 使用 Framer Motion 做意图切换动画（淡入淡出 + 滑动）

**用户体验:**

- 用户一眼就知道 Agent 在"做什么"而不是"在跑"
- 减少"它是不是卡死了"的焦虑

### 2. 思维链折叠面板 (Chain-of-Thought Collapsible) - P0

将 Agent 的推理过程从纯文本消息中提取出来，做成可折叠面板。

**设计细节:**

- 在 `MessageCard` 中增加"思维链"折叠区域
- 默认折叠，点击展开
- 使用左侧竖线时间线样式（类似 Notion 的 toggle list）
- 提取 Mentor 的 review 逻辑：为什么让 Executor 重写？看到了什么问题？

**技术实现:**

- 在 Rust 后端解析 Agent 输出，识别推理段落（通常以"让我分析一下"、"我需要"开头）
- 增加 `reasoning_chain: string[]` 字段到消息结构
- 前端使用 `Accordion` 组件展示

**用户体验:**

- 不想深究的用户不会被推理文本打扰
- 想理解 Agent 逻辑的用户可以展开查看

### 3. 瓶颈热力图迷你视图 (Bottleneck Heatmap) - P1

在 `PairDetail` 侧边栏增加一个迷你时间轴，标记迭代瓶颈。

**设计细节:**

- 水平条形色块，每个色块代表一个迭代
- 颜色编码:
  - 🟢 绿色: 正常推进（< 30 秒）
  - 🟡 黄色: 耗时较长（30-120 秒）
  - 🔴 红色: 瓶颈/卡壳（> 120 秒或反复回退）
- 悬停显示该迭代的耗时和主要操作

**技术实现:**

- 扩展 `Pair` 状态，增加 `iterationMetrics: IterationMetric[]`
- 在 `message_broker.rs` 中记录每个迭代的起止时间和事件
- 前端使用纯 CSS grid 实现迷你热力图

**用户体验:**

- 一眼看出"这里卡了 3 轮"
- 帮助用户判断是否需要人工介入

### 4. 工具调用可视化 (Tool Call Visualization) - P1

将 Agent 的工具调用（bash/read/write/search）可视化为进度步骤。

**设计细节:**

- 在消息卡片内增加微型的步骤指示器
- 已完成的步骤显示为绿色勾号
- 当前步骤显示为脉冲动画
- 待执行步骤显示为灰色圆点

**示例:**

```
[✓] 读取文件 src/utils.ts
[●] 分析代码逻辑... (当前)
[○] 写入修改
[○] 运行测试
```

**技术实现:**

- 在 `process_spawner.rs` 解析工具调用事件
- 增加 `toolCalls: ToolCall[]` 到消息结构
- 前端组件 `ToolCallSteps.tsx`

## 数据模型扩展

```typescript
// 新增/扩展的类型
interface AgentIntent {
  type: 'analyzing' | 'writing' | 'verifying' | 'reviewing' | 'waiting' | 'error'
  label: string
  icon: string
  since: number // timestamp
}

interface IterationMetric {
  iteration: number
  duration: number // ms
  toolCalls: number
  filesModified: number
  status: 'smooth' | 'slow' | 'bottleneck'
}

interface ToolCall {
  id: string
  type: 'bash' | 'read' | 'write' | 'search'
  description: string
  status: 'pending' | 'running' | 'completed' | 'error'
  startTime: number
  endTime?: number
}
```

## 成功指标

1. **用户满意度**: 发布后 2 周内调研，"你对 Agent 当前状态的清晰度"评分从当前基线提升 30%
2. **使用时长**: 用户单次任务平均观察时间增加（说明更愿意"看懂"而不是走开等待）
3. **干预频率**: 因"不知道在干什么"而手动暂停的次数减少 50%

## 技术风险与缓解

| 风险                       | 缓解措施                                             |
| -------------------------- | ---------------------------------------------------- |
| 意图识别准确率不够         | 先基于工具调用类型做规则匹配，后续可引入轻量分类模型 |
| 性能开销（实时解析推理链） | 解析在 Rust 后端异步进行，不阻塞消息流               |
| 思维链提取误伤正常内容     | 使用保守的启发式规则，宁可少提取也不多提取           |
