# v2.0.0 - 社交与分享 (Social & Sharing)

> 版本号: 2.0.0
> 主题: 社交与分享
> 目标: 让协作超越单机——分享配置、导出成果、团队协同
> 预估开发周期: 4-6 周
> 依赖版本: v1.6.0+（依赖其历史数据和分析基础）

## 核心问题

The Pair 当前是纯单机应用，存在以下痛点：

- 优秀的任务模式无法分享给团队成员
- 成功的 Pair 配置无法复用到其他机器
- 任务成果（代码变更）缺乏漂亮的总结报告
- 团队内无法对比和学习彼此的 AI 协作策略

## 功能清单

### 1. 任务报告导出 (Task Report Export) - P0

一键生成精美的任务总结报告。

**导出格式:**

**HTML 报告:**

- 响应式设计，可在浏览器中打开
- 包含:
  - 任务概览（名称、时间、模型、结果）
  - 迭代时间轴（可交互展开每轮详情）
  - 文件改动统计（图表 + 列表）
  - 关键决策点（Mentor 的重要 review）
  - 人类干预记录（来自 v1.5.0）
  - 资源使用曲线（CPU/内存）

**PDF 报告:**

- 适合放入 PR 描述或团队周报
- 固定布局，打印友好
- 封面页 + 目录 + 正文

**Markdown 摘要:**

- 适合粘贴到 GitHub PR、Notion、Jira
- 简洁格式，包含核心信息

**设计细节:**

- 在 `TaskHistoryPanel` 的每个任务卡片上增加"导出"按钮
- 导出前可预览和自定义内容
- 支持选择包含/排除敏感信息（如文件路径中的用户名）

**技术实现:**

- HTML: 使用模板引擎生成静态 HTML
- PDF: 使用 `html2pdf.js` 或后端生成
- Markdown: 纯文本模板
- 新增 `report_generator.rs` 和 `ReportExporter.tsx`

### 2. 配置模板市场 (Preset Sharing) - P0

保存和分享成功的 Pair 配置。

**模板包含:**

- 模型组合（Mentor + Executor）
- 技能文件组合
- 迭代上限和工作目录设置
- 人类偏好设置（来自 v1.5.0）
- 任务描述模板（来自 v1.8.0）

**模板市场:**

- 本地模板库：用户保存的自定义模板
- 团队共享：通过文件共享（JSON 文件）交换模板
- 官方模板：应用内置的通用场景模板

**模板卡片设计:**

```
┌─────────────────────────────┐
│ [图标] React 组件开发最佳实践    │
│ 作者: team-frontend          │
│ ⭐ 4.8 · 使用 128 次          │
│                             │
│ 模型: Claude 3.7 + Codex     │
│ 技能: frontend, testing      │
│                             │
│ [预览] [应用] [分享]          │
└─────────────────────────────┘
```

**技术实现:**

- 模板使用 JSON Schema 定义
- 本地存储在 app data 目录
- 分享通过导出/导入 JSON 文件
- 新增 `PresetManager.tsx` 和 `preset_manager.rs`

### 3. 团队配置同步 (Team Config Sync) - P1

团队内自动同步配置和模板。

**同步机制:**

- 支持 Git 仓库同步（在 `.the-pair/` 目录中存放团队配置）
- 或者 WebDAV/云盘同步
- 自动检测配置更新并提示导入

**团队配置包含:**

- 推荐的模型组合
- 共享的技能文件库
- 标准任务模板
- 项目特定的规则和规范

**权限管理:**

- 管理员可推送团队配置
- 普通成员只能拉取和应用
- 本地修改可选择覆盖或保留

**技术实现:**

- 新增 `team_sync.rs` 模块
- 检测 `.the-pair/config.json` 变更
- Git 集成使用现有 `git_tracker` 能力

### 4. 幽灵模式 (Ghost Mode) - P1

允许用户"观摩"其他配置如何处理同样任务。

**设计细节:**

- 用户输入一个任务描述
- 系统使用不同的模型组合/技能配置并行运行（后台）
- 主界面继续用户自己的配置
- 后台运行的"幽灵任务"完成后，生成对比报告

**对比报告:**

```
任务: "实现用户登录功能"

你的配置 (Claude 3.7 + Codex):
- 迭代: 12 轮
- 耗时: 8 分钟
- 成功率: ✅ 成功

幽灵配置 A (GPT-4o + Claude Code):
- 迭代: 15 轮
- 耗时: 10 分钟
- 成功率: ✅ 成功
- 差异: 使用了不同的密码哈希方案

幽灵配置 B (Gemini 2.5 + Gemini):
- 迭代: 20 轮
- 耗时: 15 分钟
- 成功率: ❌ 失败
- 原因: 缺少数据库技能
```

**技术实现:**

- 使用现有 `pair_manager.rs` 创建"幽灵 Pair"
- 幽灵 Pair 不占用前端 UI，只在后台运行
- 结果存储在临时快照中
- 新增 `GhostRunner.tsx` 和 `ghost_runner.rs`

### 5. 团队协作面板 (Team Collaboration Panel) - P2

显示团队成员的实时状态（可选开启）。

**设计细节:**

- `Dashboard` 增加"团队"标签页
- 显示团队成员当前在做什么任务
- 匿名化处理（只显示任务类型，不显示具体内容）
- 点击成员可查看其公开的成功模板

**隐私保护:**

- 完全可选，默认关闭
- 可设置共享级别：完全私有 / 仅模板 / 完全公开
- 敏感信息（文件路径、代码内容）绝不共享

**技术实现:**

- 使用点对点同步（WebRTC 或局域网广播）
- 不涉及中央服务器，保护隐私
- 新增 `TeamPanel.tsx` 和 `team_discovery.rs`

## 数据模型扩展

```typescript
// 新增/扩展的类型
interface TaskReport {
  format: 'html' | 'pdf' | 'markdown'
  content: string
  metadata: {
    taskId: string
    generatedAt: number
    includeSensitiveInfo: boolean
  }
}

interface PairPreset {
  id: string
  name: string
  description: string
  author: string
  version: string
  rating: number
  usageCount: number
  config: {
    mentorModel: string
    executorModel: string
    skills: string[]
    maxIterations: number
    preferences: HumanPreference[]
  }
  tags: string[]
}

interface TeamConfig {
  teamId: string
  name: string
  syncMethod: 'git' | 'webdav' | 'manual'
  sharedPresets: PairPreset[]
  sharedSkills: string[]
  sharedTemplates: TaskTemplate[]
  rules: TeamRule[]
}

interface GhostRun {
  id: string
  parentTaskId: string
  preset: PairPreset
  status: 'running' | 'completed' | 'failed'
  result?: GhostRunResult
}

interface GhostRunResult {
  iterations: number
  duration: number
  success: boolean
  summary: string
  differences: string[]
}
```

## 成功指标

1. **报告导出率**: 30% 的已完成任务被导出报告
2. **模板分享率**: 用户主动分享模板的比例达到 15%
3. **团队采用**: 10% 的用户启用团队同步功能
4. **幽灵模式使用**: 20% 的用户尝试过幽灵模式

## 技术风险与缓解

| 风险               | 缓解措施                                            |
| ------------------ | --------------------------------------------------- |
| 报告生成耗时过长   | 异步生成，后台处理；提供进度条                      |
| 模板分享的安全风险 | 模板 JSON Schema 验证；不包含敏感路径               |
| 团队同步冲突       | Git 冲突解决流程；提示用户手动合并                  |
| 幽灵模式资源消耗   | 限制同时运行的幽灵任务数（最多 2 个）；低优先级运行 |
| 隐私泄露担忧       | 完全可选；强调本地处理；敏感信息默认脱敏            |
