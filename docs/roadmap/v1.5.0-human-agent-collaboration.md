# v1.5.0 - 人机协作流 (Human-Agent Collaboration Flow)

> 版本号: 1.5.0
> 主题: 人机协作流
> 目标: 从"旁观"到"共舞"——让用户可以轻量、自然地干预 Agent
> 预估开发周期: 3-4 周
> 依赖版本: v1.4.0（依赖其意图数据基础）

## 核心问题

当前用户只能在 Agent 跑完后或达到迭代上限时介入，存在以下痛点：

- 看到 Agent 走偏了，但无法中途纠正
- 想给某个具体消息提意见，只能等整轮结束
- 缺乏轻量级的干预手段（非暂停/恢复这种重操作）
- Agent 不知道用户的"隐性偏好"

## 功能清单

### 1. 快捷干预面板 (Quick Action Palette) - P0

类似 VS Code Command Palette 的中途干预系统。

**触发方式:**

- 快捷键: `Cmd/Ctrl+K`
- 界面入口: `PairDetail` 右下角浮动按钮

**命令列表:**

| 命令                 | 图标 | 作用                          | 快捷键 |
| -------------------- | ---- | ----------------------------- | ------ |
| 跳过当前步骤         | ⏭️   | 让 Agent 跳过当前工具调用     | -      |
| 聚焦到文件           | 🎯   | 提示 Agent 关注特定文件       | -      |
| 给 Mentor 更多上下文 | 📋   | 注入额外上下文到下一轮 review | -      |
| 换种思路             | 🔄   | 让 Executor 尝试不同方案      | -      |
| 放慢速度             | 🐢   | 降低迭代频率，更谨慎推进      | -      |
| 加快速度             | 🚀   | 提高迭代频率，快速推进        | -      |
| 标记为关键           | ⭐   | 要求 Mentor 重点审查此部分    | -      |

**技术实现:**

- 新增 Tauri 命令 `send_intervention(pairId, intervention)`
- 在 Rust 后端 `message_broker.rs` 中处理干预事件
- 干预作为高优先级消息插入到下一轮上下文中
- 前端使用 `CmdK` 风格的搜索面板（可用现有 `fuse.js` 做命令搜索）

**用户体验:**

- 不需要暂停整个任务，轻量级干预
- 像和真人同事说话一样自然

### 2. 内联批注系统 (Inline Annotations) - P0

用户可以对某条具体消息添加批注，下轮迭代时注入给 Agent。

**设计细节:**

- 在 `MessageCard` 右上角增加"💬"按钮
- 点击展开小型输入框，用户可输入批注
- 批注显示在消息下方，带用户头像和时间戳
- 支持 Markdown 简单格式

**批注类型:**

| 类型 | 前缀 | 用途               |
| ---- | ---- | ------------------ |
| 反馈 | 💡   | 一般性意见         |
| 纠正 | 🛠️   | 指出错误           |
| 疑问 | ❓   | 不理解为什么这样做 |
| 赞赏 | 👍   | 确认这样做是对的   |

**技术实现:**

- 新增数据模型 `Annotation`
- 存储在会话快照中，与消息关联
- 在构建下一轮提示时，将批注注入为 `human_feedback`
- 前端组件 `MessageAnnotation.tsx`

**用户体验:**

- "这里写得不对" → 批注 → Agent 下一轮修正
- 批注历史保留，用户可以回顾自己的干预记录

### 3. 预测性暂停 (Predictive Pause) - P1

当检测到 Agent 陷入困境时，自动弹出轻量提示。

**触发条件:**

- 同一个文件连续 3 轮被修改
- 同一错误连续 2 次出现
- 单轮耗时超过平均值的 3 倍
- Mentor 连续 2 轮给出相同的 review 意见

**提示样式:**

- 非阻塞 toast 通知（右上角）
- 内容: "Agent 似乎在纠结 `src/utils.ts` 的逻辑，要看看吗？"
- 操作按钮: [查看] [忽略] [暂停]

**技术实现:**

- 在 Rust 后端 `message_broker.rs` 或新增 `predictive_pause.rs` 模块中实现检测逻辑
- 使用滑动窗口统计最近 N 轮的数据
- 通过 Tauri 事件通知前端

**用户体验:**

- 不等达到 `maxIterations` 才发现问题
- 用户可以主动选择是否介入，而不是被动等待

### 4. 人类偏好学习 (Human Preference Learning) - P2

学习用户的干预模式，逐渐减少需要手动干预的场景。

**设计细节:**

- 记录用户的批注和干预历史
- 识别重复模式："用户总是在代码风格问题上纠正 Agent"
- 自动生成"偏好摘要"，在 `PairSettingsModal` 中显示

**偏好摘要示例:**

```
你的干预模式:
- 67% 的批注与代码风格相关
- 经常要求 Agent 添加更多注释
- 偏好显式类型而非推断类型

建议: 在任务描述中自动追加你的代码风格偏好
```

**技术实现:**

- 新增 `preference_store.rs` 模块
- 使用简单的关键词频率统计（无需 ML 模型）
- 存储在用户本地配置文件（非会话快照）

## 数据模型扩展

```typescript
// 新增/扩展的类型
interface Intervention {
  id: string
  pairId: string
  type: 'skip' | 'focus' | 'context' | 'retry' | 'speed' | 'mark'
  target?: string // 文件路径或消息 ID
  content?: string // 额外上下文
  timestamp: number
  status: 'pending' | 'applied' | 'ignored'
}

interface Annotation {
  id: string
  messageId: string
  author: 'human'
  type: 'feedback' | 'correction' | 'question' | 'praise'
  content: string
  timestamp: number
  resolved: boolean
}

interface HumanPreference {
  category: string
  frequency: number
  examples: string[]
  autoApply: boolean
}
```

## 成功指标

1. **干预效率**: 用户单次任务中有效干预次数增加 40%
2. **任务成功率**: 因用户及时纠正而避免失败的任务比例提升
3. **认知负担**: 用户报告"控制感"评分提升（调研）
4. **学习效果**: v1.5.0 发布 4 周后，同一用户的平均干预次数下降 20%（说明偏好学习生效）

## 技术风险与缓解

| 风险                        | 缓解措施                                         |
| --------------------------- | ------------------------------------------------ |
| 干预时机不当导致 Agent 混乱 | 干预只在轮次边界应用，不中断正在执行的工具调用   |
| 批注注入导致提示过长        | 批注最多保留最近 10 条，旧的自动归档             |
| 预测性暂停误触发            | 保守策略，多个条件同时满足才触发，提供"忽略"选项 |
| 偏好学习侵犯隐私            | 所有数据本地存储，不上传；提供"清除偏好"按钮     |
