# v1.7.0 - 感官体验 (Sensory Experience)

> 版本号: 1.7.0
> 主题: 感官体验
> 目标: 让等待变得愉悦——通过声音、动画和触觉提升使用感受
> 预估开发周期: 2 周
> 依赖版本: 无（可与任意版本并行开发）

## 核心问题

当前长任务运行时，用户盯着屏幕，体验单调：

- 没有声音反馈，不知道任务何时完成
- 动画单调，缺乏叙事感
- 长时间运行后，视觉疲劳
- 任务完成时缺乏"成就感"

## 功能清单

### 1. 环境音效系统 (Ambient Audio System) - P0

为不同 Agent 活动阶段播放 subtle 的环境音效。

**音效映射表:**

| 场景            | 音效                       | 音量 | 触发条件                   |
| --------------- | -------------------------- | ---- | -------------------------- |
| Mentor 思考中   | 轻微"咔哒"声（打字机风格） | 10%  | 检测到 Mentor 正在生成文本 |
| Executor 写代码 | 低频"流动"声               | 8%   | 检测到 Executor 正在写代码 |
| 运行命令        | 终端输入声                 | 15%  | bash 工具被调用            |
| 任务完成        | 愉悦确认音                 | 25%  | 状态变为 Finished          |
| 遇到错误        | 警示音                     | 20%  | 状态变为 Error             |
| 达到迭代上限    | 提示音                     | 20%  | 迭代进度条满               |
| 人类干预被应用  | 反馈音                     | 15%  | 干预命令生效               |

**设计原则:**

- 所有音效都很 subtle，不打扰思考
- 提供"专注模式"（一键静音）
- 音效文件使用轻量 WAV 格式（< 50KB 每个）
- 支持系统音量联动

**技术实现:**

- 修复当前 `App.tsx` 中无条件预加载的问题
- 在 `useThemeStore` 中增加 `audioEnabled: boolean` 和 `audioVolume: number`
- 使用 Web Audio API 播放音效
- 音效文件放在 `src/renderer/public/sounds/` 目录
- 新增 `AudioManager.ts` 模块管理播放逻辑

**用户体验:**

- 不用一直盯着屏幕，通过声音感知任务进度
- 任务完成时的确认音带来满足感
- 专注模式下完全静音，不打扰深度工作

### 2. 微动画叙事 (Micro-Animation Storytelling) - P0

`ActivityIndicator` 不只是转圈，而是根据当前工具显示不同动画。

**动画映射:**

| 工具/状态     | 动画         | 描述                   |
| ------------- | ------------ | ---------------------- |
| `bash` 执行   | 终端光标闪烁 | 黑色方块+光标闪烁      |
| `read` 读取   | 文件打开     | 纸张展开的微动画       |
| `write` 写入  | 打字效果     | 字符一个个出现         |
| `search` 搜索 | 放大镜扫描   | 放大镜在文件图标上移动 |
| 等待响应      | 脉冲点       | 三个点依次亮起         |
| 分析中        | 神经网络脉冲 | 节点连线发光           |

**设计细节:**

- 动画使用纯 CSS + Framer Motion（不依赖外部资源）
- 每个动画时长 1-2 秒，循环播放
- 颜色随主题变化（dark/light 适配）

**技术实现:**

- 新建 `ActivityAnimations/` 目录，每个动画一个组件
- `ActivityIndicator.tsx` 根据当前工具类型渲染对应动画
- 使用 `framer-motion` 的 `variants` 和 `animate` 实现流畅过渡

### 3. 触觉反馈 (Haptic Feedback) - P1

关键事件触发系统震动。

**触发场景:**

- 任务完成（强震动）
- 达到迭代上限（中震动）
- 遇到错误（双次轻震动）
- 人类干预被成功应用（轻震动）

**平台支持:**

- macOS: 使用 `NSHapticFeedbackManager`
- Windows: 使用 `Windows.UI.Notifications`
- Linux: 跳过（无统一 API）

**技术实现:**

- 新增 Tauri 命令 `trigger_haptic(intensity)`
- Rust 后端根据平台调用对应 API
- 前端在关键状态变更时调用

### 4. 动态主题过渡 (Dynamic Theme Transitions) - P1

主题切换和关键状态变化时增加流畅的过渡效果。

**过渡场景:**

| 场景              | 过渡效果                       | 时长  |
| ----------------- | ------------------------------ | ----- |
| Dark ↔ Light 切换 | 渐变过渡，所有组件同步变色     | 300ms |
| 任务状态变更      | 状态徽章颜色渐变               | 200ms |
| 新消息到达        | 消息卡片从下方滑入 + 淡入      | 150ms |
| 迭代进度更新      | 进度条平滑增长（缓动函数）     | 500ms |
| 文件列表更新      | 新增文件淡入，删除文件缩小消失 | 200ms |

**技术实现:**

- 使用 Tailwind CSS `transition` 工具类
- 自定义缓动函数（ease-out-cubic）
- Framer Motion `AnimatePresence` 处理进入/退出动画

### 5. 呼吸式空闲状态 (Breathing Idle State) - P2

当 Agent 空闲时，界面呈现轻柔的"呼吸"效果。

**设计细节:**

- 状态徽章的边框有微弱的脉冲发光
- 背景有几乎不可察觉的明暗变化
- 资源仪表盘的数值有轻微的浮动

**目的:**

- 让用户知道应用"还活着"
- 减少静态界面的枯燥感
- 类似 Apple Watch 充电时的呼吸效果

## 成功指标

1. **音效启用率**: 60% 以上的用户启用音效（通过设置统计）
2. **满意度**: "使用体验愉悦度"评分提升 25%（调研）
3. **任务完成感知**: 用户报告"错过任务完成通知"的次数减少 70%

## 技术风险与缓解

| 风险                     | 缓解措施                                                |
| ------------------------ | ------------------------------------------------------- |
| 音效文件增加包体积       | 使用极短音效（< 1 秒），总大小 < 200KB                  |
| 动画性能问题             | 使用 CSS transform 和 opacity（GPU 加速），避免布局抖动 |
| 触觉反馈在部分平台不支持 | 优雅降级，不支持的平台静默忽略                          |
| 音效被用户感知为噪音     | 默认音量很低（10%），提供一键静音                       |
