# v1.5.0 Dashboard 仪表盘重构 - 技术设计文档

> 日期: 2026-05-02
> 状态: 待实现
> 版本: 1.5.0

## 概述

重构 Dashboard 主页，从"卡片网格列表"升级为"三段式仪表盘"。核心目标：一屏概览所有 Pair 状态，操作入口集中化，移除独立 Onboarding 页面改为空状态内嵌引导。

## 一、设计原则

1. **信息层级清晰** — 统计 → 列表 → 活动，从概览到细节
2. **操作三步内可达** — 任何常用操作不超过 3 次点击
3. **空状态不空洞** — 无 Pair 时展示引导，而非空白
4. **渐进增强** — 在现有组件基础上改造，不推倒重来

## 二、布局架构

### 3.4 PairListItem 接口

每行 Pair 的渲染组件（内联在 PairListGroup 中，不单独抽取文件）：

**Props：**
```typescript
interface PairListItemProps {
  pair: Pair
  onSelect: (pair: Pair) => void
  onPause: (pairId: string) => void
  onResume: (pairId: string) => void
  onDelete: (pair: Pair) => void
}
```

**显示内容：**
- 左侧：状态图标 + 名称（截断）+ 目录（截断，title 显示完整路径）
- 中间：StatusBadge + 当前迭代/总迭代
- 右侧（hover 显示）：暂停/恢复按钮 + 删除按钮

**行为：**
- 点击行 → 调用 `onSelect`，进入 PairDetail
- 点击暂停/恢复 → 调用对应回调
- 点击删除 → 调用 `onDelete`，触发确认弹窗

## 四、数据模型

### 4.1 统计数据来源

完全从 `usePairStore.pairs` 衍生，无需额外 Tauri 调用：

```typescript
const stats = usePairStore((state) => ({
  total: state.pairs.length,
  running: state.pairs.filter((p) => isPairActive(p.status)).length,
  paused: state.pairs.filter((p) => p.status === 'Paused').length,
  finished: state.pairs.filter((p) => p.status === 'Finished').length,
}))
```

使用 Zustand selector 确保仅在 pair 数量/状态变化时重渲染。

### 4.2 最近活动数据

新增 Rust 命令 `get_recent_activities(limit: usize)`：

```rust
#[derive(Debug, Clone, Serialize, Deserialize)]
#[serde(rename_all = "snake_case")]
pub enum ActivityType {
    StatusChange,  // pair 状态变更（finished, paused, error）
    Handoff,       // Mentor/Executor 交接
    Result,        // Executor 完成一轮
    Acceptance,    // Mentor 审核结果
}

pub struct RecentActivity {
    pub pair_id: String,
    pub pair_name: String,
    pub activity_type: ActivityType,
    pub description: String,
    pub timestamp: u64,
    pub role: Option<String>, // "mentor" | "executor"
}
```

**实现逻辑：**
- 所属模块：新建 `recent_activity.rs`，注册到 `lib.rs` 的 `invoke_handler`
- 从 session_snapshot 中读取所有 Pair 的 messages
- 过滤规则：仅提取 type 为 `handoff`、`result`、`acceptance` 的消息，以及状态变更为 `Finished`/`Paused`/`Error` 的事件
- 按时间倒序，默认取最近 10 条
- 错误处理：快照文件损坏时跳过该 Pair，记录 warn 日志，不阻塞其他 Pair 的活动提取
- 前端刷新策略：Tauri event 推送（`dashboard-activity-updated`），在 `syncFullState` 或 `onState` 回调中触发

## 五、空状态设计

### 5.1 EmptyStateGuide 内容

当 `pairs.length === 0` 时，统计卡片全显示 0，列表区替换为：

1. **标题** — "欢迎使用 The Pair"
2. **简短说明** — "两个 AI Agent，一个执行，一个审查"
3. **4 步引导** — 选目录 → 选模型 → 输入任务 → 创建
4. **主操作** — "创建第一个 Pair" 按钮
5. **次要操作** — "导入现有配置" 链接

### 5.2 OnboardingWizard 处理

- `OnboardingWizard.tsx` 不再作为独立路由页面使用
- 首次创建 Pair 时，CreatePairModal 内部集成轻量引导（3 步：选目录 → 选模型 → 输入任务）
- `OnboardingWizard.tsx` 文件保留作为引导步骤的组件库供 CreatePairModal 引用，但不再独立渲染

## 六、样式规范

### 6.1 统计卡片

复用现有 `.glass-card` 样式，每个卡片有独立的主题色：

| 卡片 | 颜色 | CSS 变量 |
|------|------|----------|
| 全部 | 靛蓝 | `--color-primary` |
| 运行中 | 绿色 | `--color-green-500` |
| 已暂停 | 琥珀色 | `--color-amber-500` |
| 已完成 | 灰色 | `--color-gray-500` |

### 6.2 列表项

每行 Pair 显示：
- 左侧：状态图标 + 名称
- 中间：状态标签 + 当前迭代
- 右侧：Hover 显示快捷操作（暂停/查看/删除）

### 6.3 活动条目

- 图标区分类型（✅完成 / ⏸️暂停 / 🔧工具 / ❌错误）
- 描述文本使用 CSS `line-clamp-2` 截断（适配多语言字符宽度差异）
- 时间使用相对时间（"2 分钟前"）

## 七、错误处理

### 7.1 数据加载失败

- 统计卡片显示 `—`（占位符）
- 列表区显示错误提示 + 重试按钮
- 活动区显示"暂无数据"

### 7.2 活动数据为空

- 显示空状态提示："当 Pair 开始运行后，这里会显示最近的活动"
- 不显示错误，因为这是正常状态

## 八、性能考虑

1. **StatCards** — Zustand selector 模式，仅数字变化时重渲染
2. **PairListSection** — `useMemo` 按状态分组，避免每次渲染重新计算
3. **RecentActivityPanel** — 后续可接入虚拟滚动（当前预计 < 50 条无需优化）
4. **QuickActionsFAB** — 使用局部 state，不污染全局 store

## 九、向后兼容

### 9.1 组件 API 兼容

- `Dashboard.tsx` 核心回调签名不变：`onSelectPair`、`onDeletePair`、`onCreatePair`
